# Rich UI 设计标准

> 这是 Rich 共享 UI 的活文档。任何新的通用界面或页面迁移都以此为默认视觉基准；当设计方向调整时，先更新本文件和对应 token，再调整页面。

## 1. Rich 的感觉

Rich 是一个深色、专业、长期使用的桌面工作台。它应当安静、清晰、信息密集，但不单调：中性炭灰建立稳定的工作背景，低饱和颜色为模块、状态和关键操作提供精确的视觉锚点。

目标不是模仿任何产品的品牌资产或页面，而是做到：

- 内容和操作优先，装饰退后。
- 密度高但不拥挤；边界、字重和色彩均服务于扫描与决策。
- 彩色元素小而有意义，形成精致的节奏，绝不成为大面积背景或噪声。
- 新页面默认使用共享原语；同类控件不自行发明样式。

## 2. 设计层级与文件归属

| 层级 | 文件 | 负责内容 |
| --- | --- | --- |
| 共享组件 API | `apps/web/src/ui/` | Button、Input、Badge、Dialog、PageHeader、EmptyState 等可复用控件；通过 `ui/index.ts` 导出。 |
| 共享 UI token | `apps/web/src/styles/tailwind.css` | `rich-canvas`、`rich-surface`、`rich-raised`、`rich-border`、`rich-text`、`rich-muted`、`rich-accent`。 |
| 历史全局主题 | `apps/web/src/theme/tokens.css` | 尚未迁移页面仍使用的全局 token；不要把新的页面设计建立在此层。 |
| 模块扩展 token | 模块目录下的 CSS | 只在模块有真实、可复用的局部语义时添加。例如项目管理的 `--pm-*`。 |

**规则：** 共享控件先进入 `src/ui`；跨页面色彩、间距和形状先进入共享 token；只有模块特有的工作流语义才能留在模块 CSS。不要把业务逻辑、接口、路由或数据模型放进 UI 层。

## 3. 基础 token

共享深色工作台采用以下层级。颜色名称描述用途，不描述某个页面。

| Token | 当前值 | 用途 |
| --- | --- | --- |
| `rich-canvas` | `#0c0c0e` | 应用或页面底色 |
| `rich-surface` | `#151519` | 主内容面板 |
| `rich-raised` | `#1b1b20` | 控件、悬浮层、表头 |
| `rich-border` | `#303038` | 低对比 1px 分界 |
| `rich-text` | `#ececf0` | 主文本 |
| `rich-muted` | `#92929d` | 辅助文本、图标、说明 |
| `rich-accent` | `#8b8ee8` | 主操作、选中、键盘焦点 |

文本使用三级层级：主内容近白、辅助信息中灰、弱提示更低对比。正常正文 13–14px，元信息 12px；页面标题 20–24px，模块标题 15–16px。使用 400/500 为主，600 仅用于关键标题和当前状态。

## 4. 彩色使用

Rich 的基础仍是中性深色；彩色用于“定位”和“理解”，而不是填充页面。

- **靛蓝**：唯一明确的主操作、当前选中和 focus ring。
- **蓝 / 青 / 紫 / 琥珀 / 玫红 / 绿**：可用于稳定的模块身份、指标分组或真实状态。采用低饱和前景、10–13% 浅底和约 30% 描边；同一屏不应让所有元素都变彩色。
- **成功 / 警告 / 风险**：只表达真实的完成、待关注或错误状态，不能用作卡片装饰。
- **允许的精致层次**：局部卡片可使用透明度极低的色彩提亮（通常不超过 11%）；不得使用强光晕、霓虹边框或大面积渐变背景。

项目管理当前采用 `--pm-*` 作为一个参考实现：导航用模块色作图标、细边框和浅底；KPI 数值继承模块或状态色；项目卡片只保留极轻的靛蓝层次。

## 5. 形状、间距与交互

- 间距只从 4 / 8 / 12 / 16 / 20 / 24px 中选择。
- 控件圆角 5–6px，面板和弹窗 8px；不用胶囊形大按钮。
- 用 1px 边框和相邻灰阶划分区域；阴影仅用于弹层，且要柔和。
- 默认按钮是低调的描边或同色系表面；每个操作组至多一个实色主操作。
- hover 仅提高一档表面明度或边框对比；active 更深；focus 必须有不刺眼但清晰的靛蓝环。
- 动效限定为 120–180ms 的颜色/边框变化；支持 `prefers-reduced-motion`。

## 6. 数据密集界面

- 表头小、弱、清晰，正文是视觉主角。
- 表格和列表使用细分割线与 hover 行底色，不用厚重卡片边框。
- badge 为小型浅底或细边框，圆角 4–6px；不要醒目的彩色药丸。
- 进度条短、细（约 4–5px），仅以一个语义色表达进度。
- 图标使用同一套线性图标和相近 stroke；不以 emoji 作为业务图标。

## 7. 新页面与迁移检查清单

1. 从 `apps/web/src/ui/index.ts` 选择现有原语；若缺失，先补充共享原语，而不是在页面里复制按钮或弹窗样式。
2. 使用共享 token；确有模块语义时，在模块根节点定义命名空间 token（如 `--pm-*`）。
3. 保持现有页面的信息架构、业务流程、数据模型与路由不变，除非需求明确要求变更。
4. 检查主操作是否唯一、状态色是否真实、焦点是否可见、列表/表格是否仍紧凑可扫描。
5. 运行 typecheck、相关测试和生产构建；对于视觉调整，在常用桌面宽度检查 hover、focus、弹层和滚动状态。

## 8. 如何演进本标准

每次调整设计时：

1. 先说明要改变的“感觉”或可见问题，而不是直接堆新颜色。
2. 在此文档更新原则、token 值和适用范围。
3. 优先修改共享 token / 原语；仅将不可共享的规则留在模块 CSS。
4. 记录是否为试验性规则，以及何时应推广到共享层。
5. 用至少一个已迁移页面验证后，再推广到其他页面。

当前设计方向：**深色中性工作台 + 低饱和模块色 + 紧凑专业的桌面生产力体验。**
