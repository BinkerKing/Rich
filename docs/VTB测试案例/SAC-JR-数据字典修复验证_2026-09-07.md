# SAC JR 数据字典修复与验证

一代依据为 `SAFE1.3/dbo.PROC_SAFE_SAC_JR.StoredProcedure.sql`。它以入参日前的最近交易日作为触发日：账户前缀受控、交易类型 `03`、金额不少于 300,000 的购汇交易中，每个账户取最晚触发时刻；再提取该触发前、起始工作日以来金额不少于 200,000 CNY 的关联交易。`workdayStart` 是一代 `GetAgoWorkDay` 的实际计算结果，由调用时传入。

已建立 `tmp_sac_jr_source` 和对应 Mapping 场景，保留一代的两条方向支路：`paymentFlag=01` 直接取账户/对手信息；`paymentFlag=02` 将对手账户转为申报账户，并清空一代同样清空的对手名称和开户行字段。

目标加工实体为 `vtb_ods.vtb.T_SAFE_SAC_JR`，应用同步目标记录为 `vtb_safe2.safe_dev.t_safe_sac_jr`。`id`、`branchId`、`dataSource`、`dataStatus` 已按一代实际目标表修复类型；`safeBranchNameId`、`rptNo`、`safeErrInfo` 在一代未写入，已改为非必填并由过程写入 NULL。

验证：Mapping SQL 通过，实体结构通过，生成 `vtb.T_SAFE_SAC_JR_extract_test_data(dataDate, workdayStart)` 成功。在可回滚事务中构造 2026-09-30 的 300,000 触发购汇和 2026-09-29 的两条 200,000 前序 CNY 交易：直接支路输出 `SACJR-OUT-01`，反向支路输出 `SACJR-OUT-02`；两者申报账号均为 `40807156SACJR`，反向支路的对手名称/开户行为空、对手账号为 `JR-EXT-02`，完全符合一代的字段转换。事务已回滚。

保留差异：通用过程固定全表 DELETE；一代 JR 过程本身不包含该清理动作，因此重跑/状态生命周期仍是生成能力层面的待闭环项。
