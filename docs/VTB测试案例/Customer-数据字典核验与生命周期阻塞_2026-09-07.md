# Customer 数据字典核验与生命周期阻塞

一代依据为 `CustomerImportServiceImpl`：遍历 CifTab，以 `Customer.BankCustomerCode = CifTab.customerId` 查询；不存在才新增，已存在客户直接跳过，不覆盖既有 `EnCode`、`EnName` 和主体类型。主体类型映射为：01/02 且证件 14 → 13；01/02 且非 14 → 12；03/04 → 11；新增客户固定启用。

当前数据字典的来源关联、仅新增过滤、六个当前实体字段和主体类型 CASE 均与一代一致，Mapping SQL 校验与过程创建成功。

事务验证揭示真实阻塞：预置 `CUST-EXIST`（`KEEP-CODE`/`Keep Name`/类型 99）后调用生成过程，通用生成器先执行全表 DELETE，随后又从 CifTab 写入 `OLD-CODE`/`New Name`/类型 13。一代应保留预置客户不变。因此此表不能通过现有通用过程获得一代等价结果；事务已回滚。

另有数据字典范围差异：一代新增 Customer 还写入英文名、地址、国别、联系电话和确认状态；当前 `vtb_ods.vtb.customer` 测试实体及其字段元只有六个可映射字段（其中 `contact_tel` 已为 SAC 测试补充），该缺口必须在客户主数据实体模型确认后补齐，不能凭空修改生产结构。
