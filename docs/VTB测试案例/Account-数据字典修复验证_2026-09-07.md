# Account 数据字典修复与验证

## 一代依据

`BaseAccDataExtractServiceImpl.getImportACCAData`：

- 输入为 `extract_ACCCA` 的 `BaseAif` 输出，以及 Customer、`AccountTypeMapping`。
- 账户键为 `COALESCE(stacod, acod) + ccy`。
- 当天未审核且操作类型为 A 的记录先清理；历史未审核记录按本次源数据覆盖。
- 已审核且已发送记录只在客户主体变化时生成状态 `12`，或在销户日生成状态 `13`；新账户只在开户日生成状态 `11`。
- `actp` 经 `AccountTypeMapping` 映射账户性质；`lmttp` 映射为 `1→13`、`2→12`、其他 `→11`。

## 二代实现

- 上游实体：`vtb.base_aif`（14 个 BaseAif 契约字段）和 `vtb.account_type_map`。
- 业务实体：`vtb.safe_account`。
- 数据字典场景：`SAFE1 ACC Account 生命周期`；临时表 `account_candidates` 在删除前构造候选集。
- 删除范围同时覆盖当日未审核 A 记录，以及本次源数据命中的历史未审核记录，确保重跑后不重复。
- 生成过程：`vtb.safe_account_extract_test_data(p_datadate date)`。

## 验证结果

- 数据字典 SQL 验证：口径及 20 个 Mapping 字段全部通过。
- 生成过程：创建并执行成功。
- 使用业务日 `2099-01-15` 的保留测试数据，连续两次执行后结果稳定。

| 用例 | 初始状态 | BaseAif 输入 | 预期/实测 |
| --- | --- | --- | --- |
| `UT-ACC-NEW` | 无既有账户 | 当日开户，限额类型 1 | 新增状态 `11`；限额类型 `13`。 |
| `UT-ACC-UPD` | 历史未审核 | 非当日开户 | 首轮按源覆盖；次轮因已变为当日未审核且非开户日，被一代语义清除。 |
| `UT-ACC-DROP` | 当日未审核 | 非当日开户 | 删除后不重建。 |
| `UT-ACC-CHANGE` | 已审核已发送 | 客户代码/名称变更 | 保留旧记录，新增状态 `12` 记录。 |
| `UT-ACC-CLOSE` | 已审核已发送 | 当日销户 | 保留旧记录，新增状态 `13` 记录。 |
| `UT-ACC-UNSENT` | 已审核未发送 | 任意源输入 | 不覆盖、不新增。 |

`extract_ACCCA` 的底层过程文本未包含在当前本地源码/数据库快照；二代已将其 Java 明确消费的 `BaseAif` 输出契约建模。过程到银行源表的贴源取数规则继续作为上游追溯项，不影响已验证的 Account 生命周期与下游 Mapping。
