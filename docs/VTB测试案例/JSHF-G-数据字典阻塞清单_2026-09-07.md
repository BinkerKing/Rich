# JSH F/G 数据字典阻塞清单

一代 `FaeManageServiceImpl.exportJSHF/exportJSHG` 从已审核、未申报的 `FAEManage` 记录直接生成报文数据，并使用关联的 `FAEBaseInfo.repNo` 与 `TxCode.txCode`。F 还使用 `UseType.useTypeCode` 和 `useDetail`。

二代测试库的 `vtb.fae_manage` 仅有 `TxCodeId`、`UseTypeId`，没有六位 `TXCODE`。库内不存在 TxCode 代码表，也没有任何可关联的 `txcode` 字段；仅存在 `vtb.use_type`。因此无法从现有二代上游还原一代 F/G 的必填监管交易编码，不能安全生成等价 Mapping 或存储过程。

现有 JSH F Mapping 将交易编码错误地指向 TransactionTab 逻辑且将多项 FAEManage 字段留空，不能作为一代一致性证据。需要补充 TxCode 维表（至少 `id → 六位 txCode`）及其与 `fae_manage.TxCodeId` 的外键/映射后，才能完成 F/G 的 Mapping、SQL、生成过程和双跑验证。
