# SAC JP 数据字典修复与验证

一代依据为 `SAFE1.3/dbo.PROC_SAFE_SAC_JP.StoredProcedure.sql`。其触发口径为：5 个工作日窗口内、账户前缀在受控清单中、交易类型 `04`、金额不少于 300,000 的触发交易；同一账户在申报日发生、金额不少于 200,000 CNY 且晚于触发时间的匹配交易生成 JP。`01/02` 收付方向采用一代的正反向账户配对。

已新建数据字典场景与临时来源 `tmp_sac_jp_source`，并将 JP 目标绑定为 `vtb_ods.vtb.T_SAFE_SAC_JP` 的加工测试实体；应用同步目标记录为 `vtb_safe2.safe_dev.t_safe_sac_jp`。补齐了测试 ODS 的 `Customer.contact_tel`，以承接一代 `ContactTel` 来源。

字段修复：`id`、`branchId` 改为 BIGINT，`dataSource`、`dataStatus` 改为数值类型；`safeBranchNameId` 不存在于一代 INSERT 列，`rptNo` 与 `safeErrInfo` 在一代均不赋值，故三者改为非必填、过程写入 NULL。其余固定值、客户编码截取、交易时间、机构信息、IP/MAC 均按一代过程配置。

验证：Mapping SQL 校验通过；实体结构校验通过；成功创建 `vtb.T_SAFE_SAC_JP_extract_test_data(workdayStart, dataDate)`。在可回滚事务中插入 2026-09-25 的 300,000 触发交易及 2026-09-30 的 200,000 CNY 后续交易，调用过程后仅输出 `SACJP-OUT-1`：客户编码 `123456789`、电话 `13800000000`、交易时间 `2026-09-30 10:00:00`、类型 `2`、客户类型 `C`、IP/MAC 均为“技术上无法抓取”，与一代口径一致；事务已回滚。

保留差异：通用生成过程采用全表 DELETE，而一代过程并未在该过程内全表删除；这是当前生成能力的过程生命周期差异，不影响本次字段与行集口径验证。
