# JSH D 数据字典阻塞清单

当前 JSH D Mapping SQL 验证返回“没有可验证的 Mapping 来源字段”，生成抽取过程同样因“没有可抽取的 Mapping 来源字段”失败。

已回读 SAFE1.3 `DataExtractMetroNewJshServiceImpl`：JSH D 的真实来源是 `RKJshtab`，以 `pstd/data_date`、币种方向、外汇账户、客户和 `RKAiftab` 资本项目校验形成 JSHTab，再输出 JSH D；并非 FAEBaseInfo 直接来源。当前 Rich 数据字典没有 RKJshtab（也没有 RKAiftab）对象，`vtb_ods.vtb` 也没有对应物理表，故没有可建立且可验证的真实来源链路。

实体结构检查还发现 11 项不一致：BUSCODE、EXRATE、FCYACC、FCYAMT、LCYACC、RPTBANK、RPTNO、SUBFLAG、CASHMARK、BUSINESSCODE 的类型/长度不一致，另有 `data_date` 冗余列。需要以 SAFE1.3 JSH D 实际提取代码和目标 HBM/DDL 逐字段确认为准后修复；目前不能凭推测改动。

因此 JSH D 尚不满足 SQL、实体、生成过程和运行样例四项门槛。
