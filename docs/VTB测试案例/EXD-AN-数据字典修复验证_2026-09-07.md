# EXD AN 数据字典修复与验证

一代/现有基准依据为 `vtb.usp_vtb_safe2_extract_exd_contracts` 的 AN 分支：仅从 `vtb.cfaa_tab` 取得 `data_type='AN'` 且 `value_date` 等于业务日的合同。`action_type` 空值转 `A`，`limit_type` 空值转 `NRA`；债务人代码在机构为 `310000167001` 或 `310000151101` 时覆盖为机构代码，其余保留来源值。目标为 `vtb.t_safe_exda_n`。

数据字典已新增场景“VTB EXD AN 自动提取”及临时来源 `tmp_exdan_source`，配置 48 个字段规则。来源 SQL 中固化了上述筛选、常量、截取和分支条件；`LIMITTYPE` 的字典长度由 255 修正为实体和一代一致的 4。表级 `extractionClearWhere` 配置为 `busdate::date = :dataDate::date AND COALESCE(invalid, 0) = 0`，使生成过程的清理生命周期与基准过程一致。

验证结果：

- 数据字典场景 API 可正常回读，48 条字段 Mapping 均可解析；
- Mapping SQL 校验通过，实体结构校验通过；
- 最新工作区 Rich 实例成功创建 `vtb.t_safe_exda_n_extract_test_data(branchId, safeBranchCode, safeBranchName, branchCode, dataDate, currentUser)`，过程按业务日且有效标识删除；
- 在可回滚事务中，插入一条 AN 主样本、AS 干扰样本、上一业务日有效存量及当日无效存量；分别运行基准过程和数据字典生成过程后，去除技术主键和审计时间字段的全表结果双向差集均为 0。两过程均保留上一业务日记录和当日无效记录，AS 干扰记录未进入 AN 结果。事务已回滚。

本表不存在未闭环的字段或生命周期差异。
