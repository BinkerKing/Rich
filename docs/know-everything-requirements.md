# Know Everything 需求文档 v0.3

## 1. 产品定位

Know Everything 是一个个人 AI 深度学习平台。用户可以输入任何想了解的知识主题，系统通过 AI 生成可视化、结构化、可持续生长的知识树，并以 HTML 页面形式呈现。

它不是普通问答工具，也不是单纯的网页生成器，而是一个面向个人长期学习、知识探索、实战转化和 AI 自我进化的学习元世界。

产品愿景：

> Know Everything 是一个个人无限学习系统。它帮助用户围绕任何主题持续生成、探索、定位、扩展和实战化知识，让用户拥有一个可以长期生长的个人知识宇宙。

核心价值：

- 帮助用户了解任何想了解的知识。
- 帮助用户从一个想完成的项目出发，反推所需知识、能力和步骤。
- 将知识可视化、结构化，便于深度学习。
- 让知识内容通过 HTML 页面承载和交互。
- 支持知识树持续展开、延伸、总结和实战化。
- 通过 AI 反馈与经验沉淀，让系统越来越懂用户。

## 2. 第一阶段范围

第一阶段先做个人学习工具，不考虑多人协作、团队权限、公开社区和共享编辑。

MVP 必须跑通以下闭环：

1. 输入主题或项目目标 -> 生成知识树 / 项目学习路径 HTML。
2. 知识元 -> 细化 / 展开 / 延伸。
3. 边栏输入修改 -> Codex 改码 -> 提交 -> 刷新并跳转到改动点。
4. 搜索框 -> 模糊定位 / AI 分析定位 / AI 接枝。

MVP 性能验收先以 1000 个元为目标，架构设计必须预留支持 10 万个元的能力。

## 3. 核心使用流程

### 3.1 输入入口与意图判断

用户输入内容可以是两类：

- 知识主题：例如“认知心理学”“产品定位”“React 动画”。
- 项目目标：例如“用 AI 做一部电影级 15 分钟短电影”“用 AI 写一篇 200 万字小说”“做一个数据分析产品”。

AI 需要先判断用户输入属于哪种意图：

- 纯学习型。
- 项目实战型。
- 产品制作型。
- 深度研究型。
- 创作型。
- 技能训练型。

不同意图对应不同展开方式。主题学习以知识结构为主，项目目标以目标拆解、能力反推和可执行步骤为主。

### 3.2 主题生成

用户输入想了解的任何主题后，AI 根据主题和用户风格要求生成学习 HTML。

生成前用户可以设置内容丰富度，例如：

- 低档：只生成必要骨架和核心元。
- 中档：生成骨架和简短解释。
- 高档：生成较完整解释、例子和学习重点。
- 深度：生成详细解释、误区、练习和延伸路径。
- 专家：生成专家视角、争议、方法论、研究或实战层内容。

第一版生成内容可以不特别细，但知识骨架和主题轮廓要尽可能齐全。

### 3.3 项目目标驱动学习

用户也可以从“我要做一个东西”出发。此时系统不应先展示一堆抽象知识点，而应先拆解目标。

目标流程：

1. 用户输入想完成的项目或作品。
2. AI 明确最终产物和约束。
3. AI 反推需要的能力。
4. AI 列出需要学习的知识元。
5. AI 组织从入门到完成作品的学习与执行路径。
6. 每一步给出可行内容、步骤和产出物。
7. 用户按路径学习和实践，最终在系统外或系统内完成作品。

项目目标驱动学习强调“可做出来”，不是只解释知识。

典型项目目标：

- 用 AI 完成一部电影级 15 分钟短电影。
- 用 AI 写一篇 200 万字小说。
- 做一个 HTML 产品 Demo。
- 做一个研究报告。
- 做一个自动化工作流。

### 3.4 进入知识树学习

用户进入生成的 HTML 后，在知识树中展开学习。知识树不是线性文章，而是由多个知识元组成的可生长结构。

每个知识点是一个“元”。每个元都支持一致的通用操作：

- 细化：把当前知识点解释得更详细。
- 展开：向下展开更多子分支。
- 延伸：朝指定方向扩展出新的相关元。
- 实战：从知识点进入实践、产品、作品方向。
- 定位：显示当前元在知识树中的位置。

### 3.5 跳出知识树后的接枝

用户学习过程中可能突然想到一个相关知识点，但不知道它属于哪个分支。此时系统需要支持“跳出知识树”输入新点。

AI 处理逻辑：

1. 判断该知识点是否可以和已有知识树关联。
2. 判断它是向下延伸、向上延伸，还是横向关联。
3. 如果可以接入已有树，则优先从已有树关联出来。
4. 补齐中间缺失的连接元。
5. 将新知识点接枝回原知识树，而不是孤立生成。

## 4. 核心概念

### 4.0 核心对象模型

系统采用“结构化数据为本体，HTML 为展示产物”的架构原则。

也就是说：

- 元不是 HTML 本身。
- HTML 只是元、组织、实战元或视图的一种展示产物。
- 元数据和关系数据应保持结构化，便于搜索、接枝、重组、复盘和生成不同展示形态。

核心对象包括：

- 元：最小知识或实践单元。
- 关系：元与元之间的连接说明。
- 组织：一组元和关系形成的局部知识结构。
- 视图：同一组元的不同展示方式。
- 页面：某个组织、实战元或总结元生成的 HTML 展示产物。
- 任务：AI 对内容、结构或代码的操作记录。
- 经验：AI 从用户反馈和复盘中沉淀出的工作规则。

### 4.1 知识元

知识元是知识树的基础节点。每个元应保持相对独立，同时具有关系信息。

知识元不需要独立版本历史。元的变化通过任务记录、代码提交或数据提交追踪。

知识元通用操作：

- 细化：把当前知识点解释得更详细。
- 展开：向下生成子元。
- 延伸：朝指定方向生成关联元。
- 实战：生成或连接实战元。
- 定位：显示当前元路径和所在组织。
- 风格调整：调整当前元或其下级组织的表达方式。
- 相同元标注：提示其他分支存在相同或相似元。

每个知识元都可以被设为新的中心。被设为中心后，系统需要重新围绕它组织当前学习界面。

### 4.1.1 元类型

不同元承担不同学习作用，因此需要分类。元类型会影响内容结构、展示方式、可用操作和学习风格。

初步元类型：

- 主题元：作为某个学习区域或项目区域的入口。
- 概念元：解释一个概念、定义、原理。
- 步骤元：描述流程、方法、操作步骤。
- 观点元：表达一种判断、立场、理论观点。
- 问题元：围绕一个问题展开学习。
- 案例元：用案例说明某个知识。
- 工具元：介绍工具、方法、框架和使用方式。
- 能力元：描述完成某类任务所需能力和训练路径。
- 项目元：描述一个想完成的目标、作品或项目。
- 实战元：把知识转化为产品、项目或作品。
- 总结元：总结一个组织或分支。
- 关系元：说明两个或多个元之间的关系。
- 争议元：展示不同观点、争议和对比。
- 练习元：用于训练、测试和巩固。

元类型不一定第一阶段全部实现，但数据结构必须支持扩展。

### 4.1.2 中心元视角

系统默认不应把整个知识树完整铺开，而应采用“中心元视角”。

中心元视角展示：

- 当前中心元。
- 当前中心元的同级知识元。
- 必要上游路径。
- 向下 2-3 层线路。
- 更深层级的折叠提示。
- 与当前学习决策相关的关键关联。
- 当前中心元的内容与操作。

用户可以在学习过程中将任意元设为中心，并从该元重新开始学习。

设计原则：

> Know Everything 不追求全量节点可视化，而追求当前学习上下文的高效呈现。

### 4.2 实战元

实战元是从知识元延伸出的产品化实践节点。

用户可以在某个知识元上触发实战，AI 从该元周围知识关系发散，协助用户做：

- 需求梳理。
- 产品分析。
- 竞品分析。
- 实战方向判断。
- 作品规划。

实战元最终产出偏“产品”。第一阶段不做特别大，主要以可跳转的 HTML 产品页面为主。

实战元页面不需要和知识树共享同一套视觉系统，可以根据具体产品定位独立设计。

实战元可以来自两种路径：

- 从某个知识元触发实战。
- 从项目目标直接生成项目路径后形成实战元。

实战元应强调可执行步骤和产出物，而不仅是知识解释。

### 4.2.1 项目元

项目元表示用户想完成的一个目标或作品。

项目元需要包含：

- 目标定义。
- 最终产物。
- 阶段拆解。
- 每阶段产出物。
- 所需能力元。
- 所需知识元。
- 所需工具元。
- 风险和难点。
- 当前下一步。

项目元的核心作用是从“我要做什么”反推“我要学什么”和“我要怎么做”。

### 4.3 总结元

随着知识树不断增长，需要总结元帮助概括一组知识元、一个组织或一个阶段。

总结元由用户主动触发生成，不默认自动生成。总结元只针对组织或分支触发，不针对单个元单独触发。

### 4.4 组织

知识树不仅有节点，还有组织层级：

- 整棵知识树是大组织。
- 某个元向下延伸的一组分支可以是中组织。
- 中组织内部继续延伸可以形成小组织。

组织可以定义局部风格。风格不一定全树统一。

### 4.5 相同元

知识树主体保持树状结构。若不同分支出现相同或高度相似的元，系统可以在元上标注“存在相同元”或“相关相同元”，但不直接把它合并成多父节点共享结构。

这样可以保持主视图清晰，避免知识树变成难以理解的复杂图。

## 5. 知识树展示与定位

整个知识树需要非常清晰的脉络，便于用户快速定位到任意知识点。

知识树展示原则：

- 不默认展示全量知识树。
- 不展示对当前学习无意义的点。
- 默认围绕当前中心元展示局部关系。
- 向下线路默认只展开 2-3 层。
- 更深层级在学习过程中逐步展开。
- 对大规模知识树，通过搜索、中心切换和局部展开进行导航。
- 每个展示元素必须说明它对当前学习有什么帮助。

定位机制采用双层策略：

1. 搜索框模糊定位。
2. AI 语义分析定位兜底。

搜索框需要支持快速模糊搜索。如果能匹配已有元，则快速定位到该元并显示它在知识树中的位置。

如果无法明确匹配，则由 AI 分析该知识点和当前知识树的关系，并判断是否需要补齐中间节点后接枝。

搜索结果说明规则：

- 如果是程序直接通过索引、标题、关键词、标签或别名匹配，应标注为程序关联。
- 如果是 AI 分析后给出的定位或接枝建议，应给出简短说明，说明为什么判断它属于该位置。

当 AI 判断新知识点和已有知识树关系很弱时，系统应创建新树。后续可以在复盘或整理时，再考虑是否做树之间的融合。

## 6. 知识元内容展示

知识树负责结构导航，知识元内容区负责真正学习。

知识元内容不应只是节点标题。用户点击或设为中心后，应看到该元对应的学习内容。

不同元类型对应不同内容结构。

概念元内容结构：

- 一句话定义。
- 核心解释。
- 为什么重要。
- 关键机制。
- 例子与类比。
- 常见误区。
- 练习问题。
- 下一步学习。

步骤元内容结构：

- 步骤目标。
- 前置条件。
- 操作步骤。
- 检查清单。
- 完成标准。
- 常见失败点。
- 下一步动作。

观点元内容结构：

- 观点表述。
- 支撑理由。
- 反方观点。
- 适用边界。
- 相关案例。
- 可验证方式。

项目元内容结构：

- 最终目标。
- 阶段路线。
- 每阶段产物。
- 所需知识。
- 所需工具。
- 风险点。
- 当前下一步。

实战元内容结构：

- 产品或作品定位。
- 目标用户或目标受众。
- 需求分析。
- 竞品或参考对象。
- MVP 功能。
- 实现路径。
- 可跳转 HTML 页面。

内容丰富度不只是内容字数不同，还会影响展示层级、解释深度、案例数量、练习任务、来源要求和实战步骤。

## 7. 风格系统

风格不仅包括 UI 风格，也包括叙事风格、表达风格、学习风格。

风格可以作用于：

- 整棵知识树。
- 某个组织。
- 某个元向下的全部分支。
- 某个实战元产品页面。

风格可以动态调整，由用户通过自然语言提出建议，AI 根据建议调整对应范围。

不同中心元可能触发不同学习风格：

- 概念元作为中心：定义、解释、例子、误区优先。
- 步骤元作为中心：流程、清单、完成标准优先。
- 观点元作为中心：论证、反方、适用边界优先。
- 主题元作为中心：模块入口、学习地图、路径选择优先。
- 项目元作为中心：目标、阶段、产物、风险、下一步优先。
- 实战元作为中心：产品化、需求、竞品、实现路径优先。

## 8. HTML 与页面划分

早期想法是每个主题生成一个独立 HTML / CSS / JS 组合包，但该策略不一定适用于大知识树。

新的原则：

> HTML/CSS/JS 组合包不固定按主题划分，而应根据知识树规模、组织边界、访问频率、实战元产物和性能需求动态划分。

建议方向：

- 元数据集中存储。
- 关系数据集中存储。
- 页面按组织、视图、实战元或高频访问区域生成。
- 大树整体保留索引、导航、搜索和加载入口。
- HTML 页面是展示产物，不一定是数据本体。

该部分是后续架构设计重点。

## 9. AI 角色体系

系统涉及多个 AI 引擎。每个 AI 本质上可以是一份类似 `codex.md` 的经验说明书。

每个 AI 说明书应包含：

- 职能范围。
- 使用的 skill 或工具。
- 工作流程。
- 经验沉淀。
- 用户偏好理解。
- 自我复盘结果。

初步 AI 角色：

- 深度研究 AI：负责知识检索、深度分析、内容补全、知识关系判断。
- UI 设计 AI：负责视觉风格、交互方式、信息展示。
- 代码开发 AI：负责 HTML / CSS / JS 生成和修改。
- 编排 AI：负责判断任务需要哪些 AI 协作，读取各 AI 经验说明书，组织任务提示词。
- 复盘 AI：负责定期分析反馈、评估经验有效性、推动 AI 自我进化。

当前后台智能执行核心暂定为 Codex。前端是操作入口，Codex 是大脑和开发执行层。

AI 说明书是项目的核心工作资产，但不强制做完整版本管理。因为说明书会根据复盘持续调整，主要关注当前有效行为。

如果某些版本信息是复盘依据或经验有效性评估的必要组成，可以为 AI 说明书保留版本记录或变更摘要。

## 10. AI 经验沉淀与自进化

AI 的经验沉淀由 AI 自己完成，不需要用户手动维护偏好等级。

系统需要通过用户一次次修正，逐渐找到最懂用户的工作方式。

AI 应自行分析：

- 哪些反馈反复出现。
- 哪些经验没有生效。
- 哪些任务结果经常被用户修改。
- 哪些工具和流程更有效。
- 哪些规则应该写入对应 AI 的说明书。

如果同类问题被用户反复提出，说明经验记录、经验调用或工作流程存在问题，应触发复盘。

## 11. 内容来源规则

普通知识学习内容不强制要求来源，以保证学习体验流畅。

以下场景需要来源：

- 深度研究。
- 实战分析。
- 竞品分析。
- 产品分析。
- 涉及事实判断、市场判断、技术选型、案例对比的内容。

需要来源的内容应提供参考链接、关键信息依据，必要时标注不确定性。

## 12. AI 改码与任务中心

用户可以通过操作边栏输入修改建议，让 AI 调整页面代码。

目标流程：

1. 用户在边栏输入修改要求。
2. 系统创建改码任务。
3. Codex 在独立分支或工作区执行修改。
4. 任务串行执行，避免版本冲突。
5. 修改成功后提交。
6. 自动验证。
7. 验证通过后自动合并。
8. 用户在任务中心看到任务完成。
9. 用户点击任务，刷新项目并跳转到改动点。

任务状态包括：

- 等待中。
- 分析中。
- 改码中。
- 验证中。
- 已完成。
- 失败。

失败处理：

- 失败任务不合并到主分支。
- 主分支保持稳定可用。
- 用户可查看失败原因、重试或生成修复任务。

改码过程中用户仍应能正常使用系统。

任务中心是辅助功能，不应占用主视野。它可以作为右侧边栏或左侧边栏的一部分，也可以支持缩小、隐藏和快速展开。

任务中心需要支持：

- 查看任务队列。
- 查看任务详情。
- 查看 AI 分析过程。
- 查看改动文件。
- 查看提交记录。
- 点击完成任务后刷新并跳转到改动点。
- 失败任务可查看原因和重试。
- 已完成任务可作为回滚依据。

## 13. 性能与架构要求

系统后续会出现大量元信息，目标需要支持 10 万级元信息的搜索、定位、展示和管理。

必须重视：

- 高效数据处理。
- 快速搜索索引。
- 知识树局部加载。
- 大规模关系存储。
- HTML 展示性能。
- AI 任务编排效率。
- 检索能力、分析能力、整理能力、UI 展示能力的持续进化。

系统不能把所有 HTML 一次性塞进页面。需要考虑索引、懒加载、分片、局部渲染和快速检索。

第一阶段数据可以先用本地文件或 JSON 实现，降低启动复杂度。但数据结构设计必须面向后续迁移到更高性能存储方案，支持 10 万级元信息。

架构原则：

- 元数据结构化存储。
- HTML 按需生成，不作为唯一数据源。
- 搜索索引独立维护。
- 知识树按组织懒加载。
- 大规模知识树不一次性渲染。
- 高频组织可缓存 HTML 展示产物。
- AI 分析使用结构化上下文，不直接读取全量 HTML。

## 14. MVP 验收标准

第一阶段 MVP 的完成标准：

1. 可以输入主题并生成第一棵知识树。
2. 可以输入项目目标并生成项目学习与执行路径。
3. 知识树以 HTML 页面展示，但底层数据保持结构化。
4. 默认采用中心元视角，而不是全量树图。
5. 中心元视角能展示同级元、必要上游和下游 2-3 层。
6. 至少支持 3 种元操作：细化、展开、延伸。
7. 支持将任意元设为中心重新学习。
8. 支持至少 4 种元类型：主题元、概念元、步骤元、实战元。
9. 不同元类型能展示不同内容结构。
10. 总结元可以由用户针对组织或分支主动触发。
11. 支持搜索已有元。
12. 搜索不到或匹配不确定时，可以由 AI 分析定位并接枝，或在弱关联时创建新树。
13. 搜索结果能区分程序关联和 AI 分析关联。
14. 支持从知识元生成或跳转到实战元 HTML 产品页面。
15. 支持边栏创建改码任务。
16. Codex 能完成一次代码修改、提交、验证通过后自动合并。
17. 任务完成后，用户可以点击任务刷新并跳转到改动点。
18. AI 能沉淀至少一条用户反馈经验，并在后续任务中体现。
19. 系统在 1000 个元的模拟数据下仍能完成搜索、定位和局部展示。
20. 架构设计说明中明确未来扩展到 10 万个元的路径。

## 15. 待重点设计问题

1. 知识元底层数据结构：JSON、数据库、图结构、文件系统如何组合。
2. 关系数据如何存储：树关系、相似元、组织归属、接枝路径。
3. 页面包如何划分：按主题、组织、实战元、访问频率还是动态策略。
4. 10 万级元信息如何搜索：本地索引、向量检索、数据库索引、AI 语义定位如何组合。
5. Codex 如何接入：CLI、桥服务、本地 agent 或其他方式。
6. AI 经验说明书如何组织和更新。
7. 任务中心如何与版本控制、分支、提交、验证、跳转联动。
8. 大规模 HTML 页面如何按需生成和加载。
9. 中心元视角如何在不同元类型之间切换展示风格。
10. 第一阶段数据是先用本地文件，还是直接设计可扩展数据库。
11. 项目目标驱动学习如何从目标反推知识元、能力元、步骤元和实战元。
12. 如何判断哪些节点对当前学习有意义，避免无效点展示。
