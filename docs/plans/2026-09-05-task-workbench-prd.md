# Rich 任务工作台 PRD

状态：按已确认交互开始实现；2026-09-05。

## 产品目标

用户在 Rich 的 Codex 聊天框选择任务模式并提出需求。AI 优先选择已有的专用承接方式；没有合适的承接方式时创建通用任务。任务工作台以可展开计划为主线，展示需求、执行步骤、关键结论、问题、材料和产物。所有交流仍发生在绑定的 Codex 对话中，工作台不另设输入框。

## 已确认原则

- 需求允许不完整：先形成当前理解，经用户确认后开始；细化需求本身可以是计划步骤。
- 每个任务绑定一个主 Codex 对话。对话可以承接多个任务，每条指令必须携带任务和步骤标识。
- 步骤可以直接执行，也可以按需展开子步骤，不强制拆解。
- 工作台按钮组装提示词并送入绑定对话，不在界面内直接调用另一套 AI。
- Codex 通过 MCP 或 CLI 写回有价值的信息，不复制完整聊天历史。
- 发出指令、对话回合结束、步骤完成、最终交付是不同事实。
- 旧应用开发数据保留，通过历史入口访问，不自动迁移或删除。

## 首版范围

1. 通用任务模式可从任意页面启动；没有交付物时也能创建 Codex 对话。
2. 通用任务独立持久化，支持 SQLite、PostgreSQL，带乐观并发检查及历史快照。
3. 需求、验收条件、疑问、项目关联、输出目标；确认需求和确认计划。
4. 层级计划、步骤状态、结论/决策/问题/进展记录、材料和中间/最终产物引用。
5. 工作台列表与三栏详情：计划树、只读步骤详情、材料与成果。统一使用 Rich 深色主题；不显示顶部英文品牌标识，顶部为窗口按钮预留 56px 空间。
6. 细化、优化、执行按钮向绑定对话发送上下文提示词；错误可见，不擅自切换对话。
7. MCP 与 CLI 共用应用服务；任务更新后工作台刷新。

Mapping 分析是首要使用场景，通用任务可记录它的材料、分析结果和数据字典目标。首版不声称自动完成数据字典批量写入：专用 Mapping 模板、发布规则校验、差异审查、原子批量同步和回读核验作为下一阶段。用户若要求首版包含该链路，再扩展本计划。

## 使用流程

1. 用户打开 Codex 对话，选择“任务模式（自动适配）”并描述需求。
2. AI 判断是否已有专用承接。通用任务通过工具创建，绑定当前 Rich 对话 ID，写入初步需求和计划。
3. 用户在对话中讨论，或在工作台确认当前需求和计划。材料缺口列入问题或步骤。
4. 用户点击“按计划执行”或“执行此步”；后端读取最新版本、确认绑定有效，向同一个 Codex 对话发送提示词。
5. Codex 写回进度、问题、结论、产物；必要时拆分步骤。遇到范围变化则更新需求/计划并重新确认。
6. 完成步骤需提供完成依据；所有必要步骤完成且有最终产物后才允许任务完成。

## 数据及行为约束

- Task：稳定 ID、标题、主对话 ID、可选项目、需求、验收条件、待明确事项、输出目标、状态、版本、确认状态。
- Step：稳定 ID、父步骤、目标、完成条件、状态、完成依据。父节点不能循环；步骤可排序。
- Record：任务/步骤范围，类型为进展、结论、决策或问题，正文、证据引用、时间。
- Resource：材料/中间产物/最终产物，标题、版本、路径或 URL、摘要、可选步骤。引用不等于上传文件或验证业务正确性。
- Command：稳定请求 ID、动作、范围、实际提示词、发送/执行状态、错误。禁止静默重放状态不明的指令。
- 每次业务写入带预期版本；冲突返回 409，要求读取最新记录后再修改。一次写入与历史快照在同一事务中完成。
- 需求和计划结构变化使对应确认失效；常规状态及进度更新不使计划确认失效。
- UI 只显示真实数据，不用示例任务填充生产列表，不依据聊天措辞推测完成状态。
- AI 写回内容不作为可执行 HTML，文件只开放显式登记的引用；不提供任意路径读取接口。

## 验收

- 没有任何项目或交付物也能打开 Codex、选择通用任务模式。
- 用 MCP/CLI 建立绑定任务，刷新页面和重启服务后数据仍在。
- 可展示两层以上计划、切换步骤、查看步骤与最终产物；详情没有聊天输入框。
- 按钮提示词包含绑定对话、任务、步骤及版本，送错/归档/忙碌对话时明确失败。
- 未确认不能执行；执行按钮不直接把步骤或任务设为完成。
- 循环计划、失效版本、无依据完成、删除已有步骤等非法写入被拒绝。
- 旧应用开发可继续查看。现有交付物模式保持可用。

## 后续

Mapping 任务模板 → 读取 published 数据字典模板 → 材料/代码/发文证据对齐 → 结构化变更集 → 校验/确认 → 幂等同步与回读。还可逐步补充步骤依赖、材料变化影响分析及任务模板库；不在首版构建通用工作流编程器。

## 材料形式补充（2026-09-05）

材料不仅是上传文件，也包含 SVN 地址、数据库连接说明、已有文件/目录地址等。资源增加可选 format（file/link/information）与 content，兼容原资源。信息无需伪造文件路径；所有形式都能关联步骤。页面只展示、展开、复制和跳转，沟通仍在绑定 Codex 对话。已有本地文件点击打开原位置，不下载副本。

材料与成果采用紧凑清单：每条默认一行，标题截断显示，保留打开/复制/展开操作。版本、说明、信息正文和路径按需展开；移除材料区的说明文字与跳转对话入口。

计划树同样按步骤单行展示，行高约 34px，保留编号、层级缩进和折叠。状态由前置圆点表示：灰色待执行、青色执行中、红色阻塞、绿色完成、暗灰色描边已跳过。完整标题和状态通过悬停提示及无障碍标签保留。

## 独立应用入口（2026-09-05）

任务工作台与应用开发拆分为应用中心的两个独立入口，不再嵌套或通过历史按钮进入。应用开发保留 practice 标识与原数据，任务工作台使用 taskWorkbench 标识。Codex 通用任务定位跳转到任务工作台；⌘7 保持打开任务工作台。

## 步骤确认项（2026-09-05）

每一步提供前置/执行中确认项。Codex 定义问题、选项及是否允许执行，用户在步骤内选择或输入答案。任务聚合保存 checkpoints，按 stepId 关联，不随计划替换丢失；版本快照和决策记录保留答复。尚未列出确认项或必填项未满足的步骤禁止执行；上级前置条件对子步骤有效。非满足条件的答案不得放行。修改已确认条件后重新核对执行状态与计划；不自动运行。提供梳理确认项按钮，向绑定对话发送具体任务/步骤范围。技术失败仍应诊断，不强迫用户承担可自动解决的问题。

待满足的必填确认项直接将对应步骤显示为红灯阻塞（包括继承的上级条件），不依赖 Codex 另行写状态；确认项满足后恢复按实际步骤状态显示。

## 播放与执行记录（2026-09-05）

顶部操作收为播放键，任务列表通过标题上方面包屑返回。右侧分为默认「步骤记录」和「材料与成果」两个页签。播放按层级顺序执行叶子步骤，以真实状态写回决定是否进入下一步；未满足前置确认项、无完成进展、运行错误、计划变更均停止。父步骤根据完成的子步骤汇总，最终交付仍需实际产物核验。记录保存实际运行时工具活动及输出摘要；运行焦点绑定当前步骤 ID，自动展开父级、选中步骤和展示对应详情，停止后保持最后位置。

### 需求版本确认规则（2026-09-05 修正）

- 首次确认前均为草稿；首次确认后才生成需求 v1。
- 已确认需求发生调整后进入待确认状态；再次确认后才生成下一个需求版本。
- 需求变更记录仅展示确认后的需求版本及相邻版本差异，确认前的多次修改不单独计版本。
- 旧的确认版本保留不变，重复确认已确认的需求不新增版本；任务内部修订计数不作为需求版本号。
