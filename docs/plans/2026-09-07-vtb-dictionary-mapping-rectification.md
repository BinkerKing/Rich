# VTB 数据字典 Mapping 修复与验证 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 逐表将 Rich 数据字典 Mapping 修复至 SAFE1.3 一代实际可执行逻辑，并对每张可修复表完成界面、SQL、生成存储过程和结果断言四项验证。

**Architecture:** 以 `43-VTB一代与二代字段级差异总台账` 和 42 份逐表核验为唯一事实来源。每张差异表独立完成“代码事实冻结 → 字典字段/口径/Mapping 修复 → SQL 生成校验 → 测试表/存储过程执行 → 结果与一代规则断言”闭环；跨表生命周期、历史和状态规则通过公共 Mapping/临时表引用实现，但验收分别回填至受影响表。

**Tech Stack:** Rich 项目管理数据字典 API、`vtb_ods` PostgreSQL 测试库、Rich Mapping SQL 校验与过程预览/执行 API、VTB 一代 Java/SQL 代码证据。

---

## 通用执行约束

1. 所有冻结范围表均逐一核验；有明确一代代码事实且可在数据字典表达的差异，直接修复。不得以“候选”状态提前要求业务决策。
2. 每张表先导出当前字段、Mapping、临时表、场景和生成 SQL，再修改；修改后必须重新读取 API 确认保存结果。
3. 验证不依赖手工页面操作：通过 Rich 项目管理 API/MCP 执行 `mapping/sql-validate`、实体结构检查、测试数据抽取 SQL 准备、存储过程生成与调用。若现有 API 缺失必要动作，只新增最小 CLI/MCP 封装，不绕过 Mapping 引擎手写替代过程。
4. 每个表的通过标准固定为：①界面/API 回读显示正确；②Mapping SQL 结构校验通过；③由 Mapping 生成的存储过程 SQL 校验通过、过程可创建并在隔离数据上执行；④结果满足该表的一代规则断言。
5. 测试仅核对业务数据与中间/报表层结果；不纳入 XML、SAFE 应用库同步、审核发送链路。但生命周期状态字段/资格条件属于 Mapping 逻辑，须按一代事实表达与验证。

## 每张表的标准步骤

1. 读取表、字段、Mapping、临时表及场景配置，保存修复前快照与引用的逐表证据。
2. 写一个针对已确认差异的失败 SQL/过程断言，确认当前 Mapping 未达到一代行为。
3. 以最小改动修复字段来源、表达式、过滤、关联、空值、历史选择或生命周期资格；R2/R3 保留显式待决标签。
4. 调用 Rich SQL 校验接口；若有临时表，逐个调用临时表 SQL 校验接口。
5. 生成抽取/过程 SQL，检查过程参数、清理范围、插入列和来源别名；执行准备/测试抽取或受控过程调用。
6. 使用场景化测试数据核验行数、业务键、字段、空值、金额精度、过滤/拒绝结果；回填工作台证据、差异台账和逐表文档。只有代码证据冲突/缺失、数据字典无法表达或环境无法执行时，记录为阻塞项并向用户汇报原因。

## 修复顺序

1. 贴源与中间层：CifTab、AifTab、BlnTab、TransactionTab、BopTransaction、Customer、Account、Balance、四张 CFA 前置表、FAL 前置表。
2. 报表层共性：生命周期/重跑保护、错误语义、三位码/映射码、历史滚动。
3. 报表层：ACC、JSH、CFA、FAL、EXD、BOP A-F、SAC JP/JR。
4. BOP A-F 先完成字段 Mapping；最终业务区分保持空/待定。BOP G/H 仅在确认一代自动链路证据后才可进入修复。

## 表级验收矩阵

工作台保留每一张范围表的独立记录，但不等于全部都要修改：每张表均先回读当前 Mapping 并比对一代实际代码；存在可表达差异时进入实际修复。BOP A-F 的字段 Mapping 必须修复，最终业务区分暂留空/待定；SAC JP/JR 已确认存在 SAFE1.3 存储过程，必须纳入修复。表级任务的具体规则来源如下：

| 组别 | 表 | 主修复主题 |
| --- | --- | --- |
| 贴源/基础 | CifTab、AifTab、BlnTab、TransactionTab、BopTransaction、Customer、Account、Balance | 入库字段、异常语义、账户/余额交易驱动、代码截断与中间字段保留 |
| CFA 前置 | CFACATab、CFACBTab、CFADATab、CFADBTab | LD 截取、客户过滤、CNY/DA 分流、空值、提款/还本/付息余额逻辑 |
| FAL 前置 | FAEBaseInfo、FAEManage、FalWarehouse | 来源白名单、历史行、机构/对象代码、异常语义 |
| ACC | ACC CA、ACC CB | 生命周期保护、源消失、余额交易聚合与关系字段 |
| JSH | JSH D、JSH E、JSH F、JSH G | `refNo` 配对、审核资格、金额/用途/汇率精度、历史重跑 |
| CFA 报表 | CFA CA、CFA CB、CFA DA、CFA DB | 前置到报表字段、空值复刻、父子关系、生命周期和同日规则 |

## 全局验证与交付

1. 汇总所有表的 SQL 校验和过程校验结果，生成一份“修复前/后 Mapping 差异及验证清单”。
2. 对每个 R1 场景执行 `48-VTB场景化双跑测试用例集` 对应的测试数据；记录一代/二代结果、SQL/过程版本和断言结果。
3. 未决 R2/R3 形成独立清单，不计入“与一代完全一致”的通过分母。
4. 更新 `43` 差异台账、`44` 规则规格、逐表核验文档以及 Rich 工作台证据；仅当所有 R1 表级任务完成且无未解释差异时，进入最终一二代双跑验收。
