# AI 任务管理 PRD

## 目标

新增一个独立的「AI 任务管理」模块，统一保存由 Codex 对话提交的 AI 任务，并让 Codex App 等 MCP 客户端主动认领、读取上下文、回写关键节点结果和等待人工 Review。

Rich 不调度或派发 Agent，不保存 Agent 处理过程、工具调用过程或完成截图。

## 提交入口

| 指令 | 场景 | 必需上下文 |
| --- | --- | --- |
| `/bug` | `bug_fix` | 当前页面定位、启动时截图、问题描述 |
| `/需求` | `requirement_analysis` | 原始想法与对话；AI 整理为 PRD 节点 |
| `/项目` | `deliverable_task` | 用户选择项目及其既有交付物 |
| 系统改造（迁移） | `system_improvement` | 旧系统改造任务的原因、PRD、相关文件与验证记录 |

## 任务信息

每个任务保存：场景及版本、标题、任务正文、初始图片和资料引用、项目/交付物关联、任务主线关系、当前状态和一段精简上下文摘要。

任务场景是外部 AI 的处理说明书。它规定场景所需输入、输出格式和安全规则。第一期仅提供内置场景，不实现学习或自动优化。

## 节点结果

外部 AI 不写处理过程，只在关键状态写一个节点：

- `analysis`：问题分析或关键判断；
- `result`：处理结果；
- `pending`：仍待处理或待用户决定的事项；
- `carryForward`：供后续任务继承的精简上下文。

节点将任务状态更新为“待 Review”或“有阻塞”。任务详情只显示这些节点、初始资料和关联任务。

## 任务主线与继续处理

Review 只有两个动作：

- **解决**：将当前任务标记为已解决；
- **继续处理**：创建新的延续任务，继承根任务、父任务的 `carryForward`、必要资料与场景。

旧任务与节点均不可被后续 AI 覆盖。

## Codex App MCP 协议

MCP 客户端可执行：

1. 列出待认领任务；
2. 原子认领任务；
3. 读取任务包（场景说明、正文、初始资料、精简上下文与父任务结论）；
4. 按需读取资料；
5. 回写一个节点结果；
6. 创建延续任务。

任务包不得默认包含完整聊天记录、工作日志或所有历史材料。

## 部署规则

Bug 默认不进行部署。只有任务正文明确要求时，`git_deploy_latest` 才表示：提交 Git、重新部署 App、在部署成功后仅保留最新 App。第一期只记录这项任务授权；实际部署仍由认领 Agent 执行。

## 迁移

现有 `improvement_tasks` 迁移为 `system_improvement` 场景任务。旧任务的 description/reason/PRD/相关文件及验证记录映射为正文、资料和节点；迁移后系统改造统一在 AI 任务管理查看。旧 API 可暂时作为兼容入口，但不可形成两套可写数据源。

## 验收标准

1. 可创建、查询、认领和读取四个内置场景的任务。
2. 同一任务只能被一个 Agent 认领；同一 Agent 可幂等重试。
3. 结果回写只创建节点并更新状态，不保存过程日志。
4. 继续处理会创建继承精简上下文的新任务，旧任务不被覆盖。
5. MCP 返回的任务包不含完整对话和无关历史。
6. 旧系统改造任务可在统一模块中可见并保留关键资料与验证结论。
7. AI 任务管理有独立页面、独立路由和独立 UI，不复用任务工作台界面。
