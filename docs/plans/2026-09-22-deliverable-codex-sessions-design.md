# 交付物 Codex Session 绑定设计

## 已确认的工作流

- 创建交付物时立即创建并绑定一个 Codex Session；初始上下文可以只有交付物标题。
- 日常入口是交付物“记录”栏的 `Codex` 标签。发布任务时必须投递到当前绑定 Session；“Codex 对话”仅用于查看与跟进该 Session。
- Codex 需要补充信息时，写入一条 `问题` 记录。问题标题和正文由 Codex 自由编写。
- 用户在该 `问题` 记录下直接答复。答复是问题的子记录，不能伪装成独立的“要求”。
- 每个 Session 有独立同步游标。首次创建或换绑后发送一次当前汇总基线；同一 Session 后续只发送游标之后新增或更新的要求、问题、答复、材料和需求说明。
- 交付物未关闭但绑定 Session 已归档时，下一次从 `Codex` 标签发布任务自动创建并绑定新 Session，并发送一次汇总基线。
- 交付物结束时自动归档绑定 Session。日后再次从 `Codex` 标签发布任务，自动创建并绑定新 Session，并发送一次汇总基线。

## 数据与边界

每条 Codex 会话保存是否为当前绑定会话，以及最后一次上下文同步的游标。每个交付物至多有一个活动绑定会话。记录扩展两个固定类型：`question` 和 `answer`；答复通过 `parentRecordId` 关联问题。现有记录和历史会话保持兼容。

Codex 通过现有交付物 MCP 写入问题记录；系统指令明确要求使用 `question` 类型，且不得把待澄清问题写进普通聊天文本。前端在问题卡片下展示答复编辑器，保存后作为 `answer` 子记录。
