# Multica 本地镜像与连接状态设计

## 目标

Rich 项目代办不再把页面读取直接绑定到 Multica CLI。Multica 继续作为任务事实源，Rich 使用本地数据库保存工作台镜像，并由后台以单项目、单任务方式每 5 秒同步任务看板。

## 数据流

1. 页面每 5 秒请求 Rich 的看板 API，API 优先返回本地快照。
2. Rich 后台为已访问项目启动一个 5 秒同步循环；同一项目同时只允许一次看板同步。
3. 首次没有快照时，API 等待 Multica 完成首轮同步并落库。
4. 小队、任务详情、评论、时间线、执行记录、Usage、PR、标签、属性、附件、元数据和订阅者按资源键保存；已有快照时立即返回，并在后台刷新。
5. Rich 发起写操作后，清理受影响的任务详情快照并立即对账看板，避免读取旧数据。

镜像始终写入 Rich 数据目录中的独立 `multica-workbench.db`，不跟随 Rich 主数据使用的 PostgreSQL 或 SQLite 配置。文件内的 `multica_workbench_snapshots` 保存 JSON 快照，`multica_workbench_sync_state` 保存连接状态、最后尝试时间、最后成功时间和错误摘要。

## 连接灯

- 绿色：最近一次同步成功，后台与 Multica 保持连接。
- 黄色：首次连接或故障后的重连正在进行。
- 红色：最近一次同步失败，或者最后成功时间已经超过 15 秒。

连接灯的悬停提示展示最后成功时间；红色状态额外展示错误摘要。同步失败时保留并展示最后一次成功快照，避免 Multica 暂时不可用导致看板清空。

## 验证标准

- 第二次读取看板不等待 Multica CLI。
- 后台同步失败时仍返回本地数据，并把状态更新为 `disconnected`。
- 正常例行同步期间连接灯保持绿色。
- 本地快照在服务重启后仍可读取。
- 同步循环防止同一项目发生并发 CLI 请求。
- 前台能够正确显示绿、黄、红三种连接状态。
