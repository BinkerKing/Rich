# Rich 工作台文档 BRD

状态：已确认业务需求，待拆分技术实现计划。  
日期：2026-09-16

## 1. 背景与目标

Rich 的任务不应只是计划、记录和材料的集合，而应成为一份随任务推进持续完善的工作台文档。任务开始时目标可能模糊；Rich 先按程序化规则收集信息，再由绑定的 Codex session 分析、讨论和执行。经用户认可的有效信息被组织为卡片，形成一份可阅读、可编辑、可迭代的说明文档。

目标是让用户在同一界面中：

- 右侧持续与 Rich 交互；
- 左侧阅读和维护有目录、有层级的工作台文档；
- 使用流程图、脑图、表格、图片、文件等合适的组件表达内容；
- 让 Codex session 通过 Rich 的 CLI/MCP 提交受控更新，而不直接修改工作台数据。

首版不追求复刻完整 Notion，也不将聊天记录、证据链或所有工具输出自动归档。

## 2. 角色与职责

### 2.1 Rich

Rich 是任务应用和工作台引擎，不具备语义推理能力。它负责：

- 用既定状态机收集、校验和补全任务信息；
- 持久化工作台、卡片树、绑定关系与最近版本；
- 根据规则调度当前任务绑定的 Codex session；
- 校验 CLI/MCP 请求、管理用户确认和执行写入；
- 渲染目录、文档流、组件预览和编辑草稿。

### 2.2 Codex session

每个任务工作台绑定一个长期存在的 Codex session。它是 Rich 内部调度的 AI Agent，负责理解已收集信息、推理、分析材料、调用 CLI/MCP、提出观点，并决定建议的工作台骨架、卡片类型和专业组件。

Codex session 不拥有数据库或任意工作台写权限。它只能通过 Rich 暴露的 CLI/MCP 提交候选或执行被允许的自动化操作。

### 2.3 用户

用户与 Rich 交互，决定哪些实质内容应成为工作台正式内容。用户可以编辑、移动、删除已生成的内容，并通过一次统一保存使手工修改生效。

## 3. 任务生命周期

1. 新任务创建时没有预制章节骨架，只有空白工作台和右侧交互区。
2. Rich 程序化收集最小任务信息，例如任务描述、已知材料、期望结果和明显限制。
3. Rich 调用绑定的 Codex session。session 根据上下文判断任务性质：继续提出需要收集的信息，或建议最小文档骨架。
4. session 认为合适时可自动创建、调整或删除空标题骨架。标题是低风险组织行为，不阻断讨论，也不要求用户确认。
5. 进入分析、讨论或执行时，session 遇到需要沉淀的新观点、方案或组件，先通过 Rich 提出简短的工作台更新意图。
6. 用户接受后，Rich 保存该 AI 更新包并刷新工作台；用户可随后手工修改或删除。

## 4. 工作台文档模型

### 4.1 卡片树

一份工作台文档是一棵由卡片组成的树。卡片具有稳定 ID、父节点、排序位置、类型、标题、内容和属性。目录编号由父子关系和排序实时推导，例如 `1`、`1.2`、`1.2.1`；编号不是主键，移动卡片后可以变化。

卡片可拖动排序、缩进形成层级、折叠或删除。目录负责阅读顺序，工作台不强制建立额外的证据或引用关系网络。

### 4.2 轻量文档流

工作台主区域采用接近 Notion 的连续文档流：普通标题、段落、清单和观点块默认没有边框；悬停或选中时显示块操作、拖拽与编辑入口。目录为工作台内部的可收起窄栏，用于定位和浏览层级。

该目录是内容级的“快速定位器”，类似项目说明中的章节定位：它只反映当前工作台的卡片树、编号、折叠和阅读位置，点击后定位正文中的对应内容。它不是应用级导航，不承载页面跳转、功能菜单或跨应用路由。

只有组件型卡片显示明确容器边框，例如流程图、脑图、图片、文件、链接和表格模块。卡片是 Rich 的统一数据与操作单位，但不要求在视觉上全部呈现为方框。

### 4.3 卡片类别

| 类别 | 例子 | 事实源与行为 |
| --- | --- | --- |
| 内容卡片 | 标题、段落、清单、观点、结论 | 内容保存在工作台，提供接近 Notion 的编辑体验。 |
| 结构卡片 | 章节标题、可折叠容器 | 决定目录、编号和层级；空标题可由 AI 自动编排。 |
| 内置模块卡片 | 问题清单、风险清单、预制对比表 | Rich 提供预定义字段、校验与渲染，AI 自行选择合适模块。 |
| 功能卡片 | 流程图、脑图、任务、数据表 | 绑定 Rich 专业应用中的实体，在文档中预览，编辑跳转到专业应用。 |
| 嵌入卡片 | 图片、文件、网页链接 | 在工作台中以带边框组件展示。 |

## 5. 组件与绑定

流程图、脑图等专业内容不在工作台中复制一份数据。功能卡片仅保存对 Rich 专业应用实体的绑定、标题、说明及显示设置；专业应用仍是图形数据、编辑和版本的唯一事实源。工作台负责显示预览、提供打开入口并将其放入正确的文档语境。

表格使用 Rich 已有的预制模块能力，而不是独立表格应用。AI 在可用模块目录中自行选择，例如选择“问题清单”承载待确认问题。表格模块有标题、字段、行、状态和排序，整体作为工作台组件卡片显示；其手工编辑随工作台统一保存。

普通卡片不强制记录出处或证据。工作台首要是一份说明文档；系统可保留必要的内部操作与版本信息用于恢复和排错，但默认不把来源元数据展示为正文。

## 6. Rich 与 Codex session 的受控协作

Codex session 通过 Rich CLI/MCP 读取当前工作台、任务信息和可用能力目录，并提交结构化请求。Rich 是唯一写入边界。

当 session 想沉淀实质内容时，Rich 向用户展示意图级确认，而非底层字段 diff。例如：

> 我将补充“异常需要人工复核”这一观点，并新建一张流程图解释处理路径，放入「2.1 异常处理」下。

用户可接受、要求调整或暂不写入。一次接受可对应多个连带动作：创建观点卡片、创建或绑定流程图、插入功能卡片、设置层级与顺序。Rich 将整个更新包作为一次原子 AI 更新保存，避免半完成状态。

骨架标题的自动创建、移动、改名、合并和删除属于低风险组织行为，可直接由 AI 通过 Rich 落盘；带有正式观点、结论、方案、表格数据、流程图或外部绑定的实质内容需要上述意图确认。

## 7. 保存、编辑与版本规则

### 7.1 AI 更新

AI 自动创建的标题骨架，以及用户接受的 AI 内容更新，均立即保存为工作台正式版本。保存成功后，AI 可将最新正式内容作为后续讨论的上下文。

### 7.2 用户手工编辑

用户对已有内容的修改、移动、层级调整、解绑或删除，进入整份工作台唯一的本地编辑草稿。页面显示“有未保存更改”；用户点击统一的“保存工作台”后，整份卡片树成为新的正式版本。用户可在保存前取消草稿。

不提供每卡片独立保存。工作台仅保留当前正式版本和最近 3 个历史版本，以支持有限恢复。

### 7.3 优先级与覆盖

AI 的正式写入优先于用户尚未保存的手工草稿。若 AI 创建或更新工作台内容，Rich 直接以最新正式版本覆盖当前未保存草稿；不排队、不合并、不保留该草稿。用户只有统一保存后，手工修改才会成为后续 AI 可读取的正式内容。

## 8. 界面要求

桌面布局为左右两大栏：

- 左侧工作台约占主宽度的 65%，内部含可收起的内容快速定位器与文档流；
- 右侧 Rich 对话约占 35%，显示程序化收集、Codex session 的讨论结果、工作台更新意图及输入区；
- 当前选中卡片可作为右侧讨论上下文；
- 窄屏时对话区以抽屉呈现，文档保持主要阅读空间；
- 用户可通过接近 Notion 的块编辑、`/` 插入和拖拽完成内容操作；流程图等功能卡片只提供预览与“打开编辑器”。

### 8.1 Rich 视觉与组件一致性

工作台文档是 Rich 的独立应用，不是独立设计语言。它必须沿用 Rich 现有的色彩 token、字体层级、圆角、阴影、间距、悬停/禁用/加载状态、图标语言和键盘交互约定；按钮、输入框、菜单、提示、确认操作和空状态应与应用中心及现有专业应用保持一致。最终验收以完整页面和关键交互的视觉效果为准，不能只满足功能或组件单测。

右侧对话区中可复用的 UI（会话消息、输入框、附件投放、流式状态、错误提示、更新意图确认卡）应抽成 Rich 通用组件库，由原有 Codex 对话入口和工作台文档右栏共同使用。新应用不得复制一套视觉相近但行为不同的聊天组件；公共组件应拥有明确的受控输入和回调接口，业务页面只负责绑定会话及处理工作台 proposal。

## 9. 首版验收标准

1. 新任务开始时没有固定模板；Rich 收集信息后，Codex session 能创建可调整的最小标题骨架。
2. 工作台以可编号、可嵌套、可拖动的轻量文档流展示，目录与正文位置一致。
3. 普通内容块没有统一卡片边框；流程图、脑图、图片、文件、链接和表格模块有组件容器。
4. Codex session 只能通过 Rich CLI/MCP 请求工作台更新，不能直接写数据库。
5. 实质 AI 更新先向用户展示简短意图；一次确认可原子落地多个连带卡片与绑定。
6. 流程图卡片绑定现有流程图应用实体，能预览并跳转编辑，不复制图数据。
7. AI 能从 Rich 的预制表格模块中自行选择并创建如“问题清单”的表格组件。
8. AI 写入即时成为正式版本；用户手工编辑整份文档后必须点击统一保存才能生效。
9. AI 写入会直接覆盖未保存的用户草稿；系统只保留最近 3 个版本。
10. 文档正文不要求显示来源、证据或 Agent 标签。
11. 工作台整体视觉、按钮、排版和交互状态与 Rich 保持一致；通用对话 UI 由 Rich 组件库复用，不出现第二套聊天界面。

## 10. 非目标

- 首版不构建自由画布或空间化卡片布局。
- 首版不复刻完整 Notion 数据库、公式、协作权限或无限插件生态。
- 首版不在工作台中重做流程图、脑图等专业应用的编辑器。
- 首版不自动把全部聊天、文件或工具输出写入工作台。
- 首版不要求所有普通内容绑定出处或证据链。
