# 计划管理 · 多计划架构设计

> 把「伟大的我」重塑为以「计划」为核心的 AI 计划管理系统。
> 用户提一个目标 → Rich/Hermes 帮拆解成 年/月/周/日 → 用户在多个计划间并行跟进。

## 1. 名词定义

| 术语 | 定义 |
|---|---|
| **计划（Plan）** | 用户的一个顶层愿望，独立于年/月/周。例："3 个月减 10 斤"、"读完《思考快与慢》"。**多个计划可并行**。 |
| **目标（Goal）** | 计划在某个时间尺度（年/月/周）下的子目标。一个计划下可以有多个层级的 goal。 |
| **任务（Task）** | 天级的具体动作。挂在 goal 下，goal 挂在 plan 下。 |
| **拆解（Decompose）** | Rich/Hermes 把用户的自然语言目标变成年/月/周/日 goal+task 结构的工作流。 |

> 关键关系：`Plan → Goal[]（年）→ Goal[]（月）→ Goal[]（周）→ Task[]（天）`
> 单计划可以**跳过**某些层（"减肥 3 个月" 不需要年度 goal）。

## 2. 用户故事

**S1 · 用 Rich 创建计划**
> 我跟 Rich 说："我想 3 个月减 10 斤"。Rich 跟我对话搞清楚时间窗、强度偏好、可执行频次，然后生成一份 plan 草稿（月×3 / 周×13 / 每周 N 个 task 模板）。我在预览面板里看完，可以单条改动，点"采用此计划"才真正写入。

**S2 · 手动建计划**
> 我点首页右上「+ 新建计划」→ 弹窗填标题、起止日期、要不要 AI 协助。要 → 跳到 S1；不要 → 直接进单计划详情页空架子，自己手动添加 goal/task。

**S3 · 多计划首页**
> 打开计划管理 → 看到 3 个进行中的计划卡片（减肥 25% / 读书 40% / 学 React 60%），每卡有一条进度条 + 今日 N/M 任务 mini。点任意卡进入该计划详情。

**S4 · 单计划深钻**
> 进入「减肥」详情 → 头部 hero 卡 + tab 切换 [总览|月度|周度|今日]：
> - 总览：里程碑节点 + 整体趋势线
> - 月度：5 月 / 6 月 / 7 月 的 kanban
> - 周度：当前周和后续 12 周的 kanban
> - 今日：本计划下今天 N 条 task，可勾可改

**S5 · 今日合并视图**
> 回首页 → 一个 "今日任务" widget 把所有计划下今天的任务合并展示（带"来自哪个计划"标签），方便一次性勾选。

**S6 · 跟 Rich 报告**
> 我在 HQ 对话里说"今天跑了 5km，没忍住喝奶茶"。Rich 解析后：
> - 找到本周「减肥」周计划下名为"晨跑"的 task，勾上
> - 把"奶茶"作为阻碍写入今天的 victoryBlocker
> - 提议明天 task："多喝水 2L"
> 我看到 Rich 提议的写入操作（带预览），点确认才落库。

**S7 · 计划归档 / 完成**
> 减肥目标达成或放弃后，我可以归档计划。首页只显示"进行中"，归档区单独看。

## 3. 信息架构

```
计划管理 (顶层入口)
├── 首页 (全计划仪表盘)
│   ├── 计划卡片 ×N (减肥/读书/...)
│   └── 今日跨计划合并任务
├── 计划详情 (单计划深钻，每个 plan 一个)
│   ├── Hero (标题 + 进度 + 时间窗)
│   └── Tab 切换
│       ├── 总览  (里程碑 + 关键指标 + 战术地图)
│       ├── 月度  (kanban: 月目标 + 进度)
│       ├── 周度  (kanban: 周目标 + 进度)
│       └── 今日  (该计划下今天的 task)
├── HQ 对话 (Rich/Hermes 聊天)
│   ├── 默认模式：闲聊
│   ├── 拆解模式：新建计划时触发
│   ├── 报告模式：日常同步进度
│   └── 复盘模式：周末回顾
├── 数据分析 (跨计划趋势)
├── 每周复盘
└── 设置
```

**侧栏变化**：把当前的"目标管理 / 事件洞察"合并到「计划详情」里，侧栏只留 5 项：首页 / 计划详情（动态切换）/ HQ 对话 / 数据分析 / 设置。

## 4. 数据模型

### 4.1 新增表：plans

```ts
interface Plan {
  id: string;
  title: string;              // "3 个月减 10 斤"
  detail?: string;            // 详细描述
  start: string;              // ISO date "2026-05-01"
  end: string;                // ISO date "2026-07-31"
  scopes: Scope[];            // ["month", "week", "day"] — 这个计划跳过 year
  status: "active" | "archived" | "completed";
  source: "user" | "ai-decompose"; // 谁建的
  createdAt: number;
  archivedAt?: number;
  /** 拆解溯源：哪次 Rich 对话产生的（可空，手建为 null） */
  aiTrace?: { messageId: string; conversationId: string; decomposedAt: number };
}

type Scope = "year" | "month" | "week" | "day";
```

### 4.2 Goal 扩展

```ts
interface Goal {
  // 已有
  id: string;
  scope: "year" | "month" | "week";
  title: string;
  detail: string;
  phase: Phase;
  due: string;
  progress: number;
  createdAt: number;

  // 新增
  planId?: string;            // 必填（除"野生" goal 兼容旧数据）
  parentId?: string;          // 上一层 goal 的 id；year→month→week 链
  source: "user" | "ai" | "ai-confirmed";
  /** 量化指标（可选）：让 "跑步 12km" 这种数值目标可以画曲线 */
  metric?: { unit: string; target: number; actual: number };
}
```

### 4.3 Task 扩展

```ts
interface Task {
  // 已有
  id: string;
  title: string;
  done: boolean;
  date: string;
  badge: string;
  goalId: string;             // 已存在，通过 goal 反查 plan
  note: string;

  // 新增
  source: "user" | "ai" | "ai-template"; // 区分手加 / AI 加 / 从周计划模板生成
  /** 量化字段：如"跑 5km" 实际跑了多少 */
  metric?: { unit: string; target: number; actual?: number };
  /** 软删除标记，让用户可撤销 AI 加的项 */
  archived?: boolean;
}
```

### 4.4 数据迁移

现有 `state.goals[]` 是平铺的、无 planId：
- 启动时检测：每个 goal 没 planId → 自动归到一个名为「未分组」的兜底 plan
- 用户可以稍后把它们手动迁到正式 plan
- 不丢数据、不破现有 UI

## 6. AI 工作流

### 6.1 拆解模式（decompose）

**输入**：用户的目标描述 + 起止日期
**输出**：结构化 JSON

```json
{
  "plan": { "title": "3 个月减 10 斤", "start": "2026-05-01", "end": "2026-07-31", "scopes": ["month","week","day"] },
  "goals": [
    { "scope":"month", "title":"5月减 3.3 斤", "parentRef":null, "metric":{"unit":"斤","target":3.3,"actual":0} },
    { "scope":"week",  "title":"周 5/18-5/24：跑 3 次", "parentRef":"month-0", "metric":{"unit":"次","target":3,"actual":0} },
    ...
  ],
  "dayTemplate": [
    { "title":"晨跑 30 分钟", "metric":{"unit":"km","target":5}, "weekdays":[1,3,5] },
    { "title":"三餐记录", "weekdays":[1,2,3,4,5,6,0] }
  ]
}
```

UI 解析后渲染预览，用户确认后：
- 一次性创建 Plan + 所有 Goal（解析 parentRef → 真正的 parentId）
- 把 dayTemplate 在每周日凌晨展开成下周 7 天的 Task（或立即展开本周）

**system prompt** 存在 [ai/decompose.md](ai/decompose.md)（新建）。

### 6.2 报告模式（report）

**输入**：用户一句话 + 当前进行中的 active goals + 今日 tasks
**输出**：一组写入操作（带预览）

```json
{
  "operations": [
    { "kind":"tick_task", "taskId":"...", "actualMetric": 5 },
    { "kind":"append_daily", "field":"victoryBlocker", "text":"阻碍：奶茶没忍住" },
    { "kind":"suggest_task_tomorrow", "title":"多喝水 2L", "goalId":"..." }
  ]
}
```

UI 渲染"建议变更"，用户点"全部采用 / 单条选择 / 拒绝"。

### 6.3 复盘模式（review）

定时（每周日 22:00）或主动触发：
- Hermes 读本周 task done 数据 + daily 4 槽 + 体重曲线
- 输出复盘草稿（写入 reviews[]）+ 下周计划建议（预览）
- 用户编辑确认后落库

## 8. 待决问题

| # | 问题 | 倾向 |
|---|---|---|
| 1 | 跨计划任务冲突（同时间两个计划都要做）| 不报警，列表里同时显示，用户自己决定 |
| 2 | 一个 task 能挂多个 goal 吗？| 不能。简化模型 |
| 3 | Plan 归档后，挂在它下面的 goal/task 怎么办？| 一起归档，不在首页显示，但搜索能找到 |
| 4 | 用户改 plan 起止日，已生成的 task 怎么办？| 弹窗问：保留 / 截断 / 重新展开 |
| 5 | AI 拆解的 plan 用户改过后，再让 AI"重新调整" | 把当前状态 + 用户改动作为新 context 发给 Hermes |
| 6 | 多人协作 | 暂不支持，单机版 |

## 9. 不在本设计范围内（YAGNI）

- 移动端 app
- 跨设备同步
- 通知推送（提醒今天该跑步了）—— 留到 Stage 5 之后
- 智能排程（自动避开周末/节假日）
- 第三方数据接入（Apple Health / 微信运动）
