# 可配置问题清单表格实施计划

> 目标：将测试中心的问题清单改为基于 `react-data-grid` 的可复用数据表，支持单元格编辑、增行、自定义列、冻结列和项目级持久化设置。

## 范围与约束

- 新组件放在 Web 共享组件目录，不耦合测试中心字段；其他模块通过列定义和保存回调复用。
- 问题记录继续保留与测试用例的关联；新增问题时必须选择来源用例，避免生成失去追溯关系的空记录。
- 表格列设置按项目写入现有测试中心 SQLite 数据库。测试中心的数据目前是本机执行数据，因此设置会跨应用重启保留，但不会自动同步到另一台机器。
- 不引入 AG Grid 等商业高级功能；使用 MIT 的 React Data Grid。

## 实施步骤

1. 加入 `react-data-grid` 依赖，并为共享组件补充覆盖关键能力的测试。
   - 验证：Web 类型检查和组件测试能加载 DataGrid。
2. 创建 `ConfigurableDataGrid`：渲染可编辑网格、工具栏、列设置面板；接受受控列定义和行更新回调。
   - 验证：测试断言支持新增行、自定义列、冻结列、设置面板与 DataGrid 渲染。
3. 扩展测试中心问题 API 和 SQLite 模型：保存问题自定义字段与项目的网格列设置。
   - 验证：路由/仓库测试覆盖自定义字段及设置的读写，旧数据默认值安全。
4. 将问题清单工作台替换为网格，保留状态筛选、问题详情、讨论与复测操作；新增问题提供来源用例选择。
   - 验证：TypeScript 构建、服务端测试与手动检查 VTB 二代项目中两条既有问题不丢失。
5. 按桌面应用流程重建并启动 Rich，检查编辑、增列、冻结列与重启后设置仍在。

## 验收标准

- 问题列表由共享 DataGrid 组件展示，而非页面内私有表格。
- 可直接编辑标题、描述、负责人、外部编号、状态及新增自定义列；修改会持久化。
- 用户可新增问题、增加自定义列、冻结/取消冻结列；列设置会持久化。
- 已有问题记录、详情讨论和复测流程保持可用。
