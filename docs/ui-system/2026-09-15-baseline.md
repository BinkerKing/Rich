# Rich UI System Baseline

## Canonical direction

The first Rich UI-system milestone uses a quiet near-black dark application surface, neutral borders, bright readable text, restrained violet/blue interaction emphasis and Lucide line icons. New common UI must avoid page-level gradients, colored icon containers, decorative card grids, redundant timestamps and repeated labels.

## Current application structure

- `apps/web/src/App.tsx` selects application routes directly from Zustand state; it does not use a global page-shell component.
- `apps/web/src/theme/tokens.css` is the existing global token source and installs global body, focus and scrollbar styling.
- `apps/web/src/components/TopBar.tsx` is shared by a subset of legacy routes through `.tv-*` classes defined in `apps/web/src/views/TreeView.css`.
- `apps/web/src/views/DeepWorkbenchView.tsx` is the first UI-system pilot. It has a full-screen mind-map canvas and a resizable node-detail panel with four persisted content sections.

## Migration classes

| Class | Routes | First-pass treatment |
| --- | --- | --- |
| Standard application pages | Projects, App Launcher, project-management workspaces | Adopt `RichAppShell` and common UI primitives progressively. |
| Canvas workspaces | Deep Workbench, mind map, flowcharts | Keep canvas implementation; use the shell only around reading or detail modes. |
| Overlay surfaces | chat, break reminder, task overlay | Do not place under the common shell. Migrate only shared controls later. |
| Legacy chrome | Home, Tree, Admin | Keep current `.tv-*` styling until a dedicated migration task. |

## Baseline checks

- Production build completed on the isolated `codex/rich-ui-system` branch before UI changes.
- Existing build warnings concern static and dynamic imports of `apps/web/src/api/client.ts` and oversized production chunks; they are not introduced by this UI plan.
- The main worktree contains uncommitted DeliveryWorkspace changes. They are intentionally excluded from this branch and every UI-system commit.
