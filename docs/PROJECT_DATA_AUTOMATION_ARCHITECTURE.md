# 项目管理：数据自动化架构

## 目标

数据自动化负责对数据字典中已经存在的 SQL 验证、实体表同步、抽取准备和取数能力进行编排，不复制数据字典的 SQL 生成逻辑。第一期采用严格串行语义：分组按 `sort_order` 执行，组内表按 `sort_order` 执行，每张表固定执行四个步骤。

```text
SQL 验证 → 表结构创建/同步 → 抽取存储过程准备 → 执行取数
```

任何步骤失败后，当前批次进入 `paused`，后续表保持 `pending`。断点续跑从失败步骤重新执行，已成功步骤和表不会重复运行；重新运行会生成一份新的批次快照。

## 模块边界

- `project-automation/application`：严格串行状态机、运行服务、数据字典步骤适配。
- `project-automation/contracts.ts`：方案、分组、表项、批次和仓储契约。
- `project-automation/infrastructure`：PostgreSQL 与 SQLite 持久化。
- `project-automation/presentation`：配置、启动、轮询和续跑 HTTP 接口。
- `AutomationWorkspace.tsx`：项目管理中的配置和运行界面。

自动化模块只通过数据字典 application service 执行表操作。数据库方言、Mapping 解析、存储过程生成和实体表同步仍由数据字典模块负责。

## 持久化与恢复

配置使用 `pm_automation_plans/groups/items` 三张规范化表。运行使用 `pm_automation_runs/run_items`，启动时把分组名称、表名称、排序和步骤状态复制为不可变快照，避免运行期间的配置修改改变当前批次。

每次状态变化都会保存运行项目及四个步骤的状态、错误、开始/结束时间和 `affected_rows`。页面刷新后可从数据库恢复；失败错误包含 `table_id`，界面据此跳转到数据字典对应表的 Mapping。

## 参数预检与批次参数

执行前通过 `POST /automation/plans/:planId/check` 严格按配置顺序检查全部表的抽取逻辑。预检复用数据字典的抽取 SQL 解析与运行参数识别能力，但使用 `dryRun`，不创建存储过程、不更新表结构、也不执行取数。返回结果包含：

- 全方案去重后的参数名称、类型及引用表；
- 每张表的检查状态、参数名称和错误；
- 方案是否已具备执行条件。

运行参数属于一次运行批次，而不是方案配置。参数保存在 `pm_automation_runs.runtime_params`，并由执行上下文统一传给 SQL 验证、抽取准备和取数步骤。断点续跑允许更新同一批次参数，避免修正参数后生成新的批次，且已成功步骤仍不会重复运行。

此决策保持了三个边界：数据字典负责识别 SQL 参数，自动化模块只负责聚合和编排；检查操作无业务数据副作用；历史运行保留当时使用的参数，便于定位和复现问题。

## 验证边界

- 状态机测试：严格顺序、失败即停、断点续跑。
- 仓储测试：配置层级、排序、运行快照和步骤恢复。
- 适配测试：四个步骤调用既有数据字典服务，SQL 验证错误转换为暂停错误。
- 路由测试：配置方案并异步运行，轮询获得记录数。
- 预检测试：跨表参数去重、类型合并、单表错误保留、检查过程无 DDL/取数副作用。
- 参数测试：批次参数持久化，并透传全部执行步骤和断点续跑。
- 项目回归：服务端测试与类型检查、Web 类型检查和生产构建。
