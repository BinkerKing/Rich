# 数据字典整理输入模板

本文档用于项目数据字典整理。请按模板填写；没有可靠证据的内容写 `待确认` 或留空，不要猜测。Agent 导入前会按模板校验，不符合要求的内容不会写入正式元属性。

## 1. 填写总原则

1. 数据字典不是普通字段清单，而是可追溯的元数据工作台。
2. 所有表名、字段名、中文名、类型、长度、格式、Mapping 来源都必须有证据。
3. 证据可以是发文、数据库注释、DDL、SQL、存储过程、代码、文件样本、接口文档、业务确认记录。
4. 中文名不能由英文名机器翻译，不能复制英文名充数。
5. 类型、长度、格式分开填写，不要混在一个属性里。
6. Mapping 表示“数据怎么来的”；字段结构、文件结构、XML 节点结构本身不是 Mapping。
7. 没有来源逻辑证据时，Mapping 不填写。

## 2. 库元模板

```markdown
## 库元

| 属性 | 填写内容 |
| --- | --- |
| 库编码 | 例如：SAFE_SOURCE / SAFE_STAGE / SAFE_MESSAGE |
| 库名称 | 例如：SAFE 源数据层 |
| 系统类型 | source_system / ods / data_mart / reporting / message / integration / other |
| 资产层级 | 源数据层 / 贴源层 / 中间层 / 报表层 / 报文层 / 公共层 |
| 用途说明 | 说明这个库/层在加工链路中的职责 |
| 连接信息 | 有则填写；无则写 待确认 |
| 证据来源 | 文件名、发文、代码路径、SQL、访谈记录等 |
| 备注 | 可空 |
```

## 3. 表元模板

```markdown
## 表元：表英文名

| 属性 | 填写内容 |
| --- | --- |
| 所属库 | 例如：SAFE_MESSAGE |
| 英文名 | 数据库表名 / 文件名 / 报文名 / XML结构名 |
| 中文名 | 例如：[报文]组织机构基本情况表 |
| 分组 | 客户 / 账户 / 交易 / 外债 / 组织机构 / 公共代码等 |
| 数据层级 | 源数据层 / 贴源层 / 中间层 / 报表层 / 报文层 |
| 载体类型 | 数据库 / 文件 / XML报文 / TXT / Excel / 接口 / 待确认 |
| 表口径 | 这张表、文件或报文承载什么业务数据 |
| 生成方式 | 直接落地 / 文件解析 / SQL加工 / 存储过程 / 接口生成 / 待确认 |
| 上游来源 | 上游表、源文件、接口、人工录入等；无证据写 待确认 |
| 下游去向 | 目标表、报表、报文、接口等；无证据写 待确认 |
| 证据来源 | 文档路径、SQL路径、代码路径、截图、访谈记录等 |
| 备注 | 可空 |
```

### 表元填写规则

| 属性 | 规则 |
| --- | --- |
| 英文名 | 保留数据库表名、文件名、报文名、XML 结构名等原始名称 |
| 中文名 | 使用业务可读名称，不能用表口径代替 |
| 数据层级 | 只能填写：`源数据层`、`贴源层`、`中间层`、`报表层`、`报文层`、`公共层` |
| 载体类型 | 说明表元的承载形式，例如数据库、文件、XML、接口 |
| 表口径 | 说明该表/文件/报文承载什么业务数据 |
| 证据来源 | 必须能定位到原始依据 |

中文名推荐格式：

| 场景 | 推荐格式 | 示例 |
| --- | --- | --- |
| 源文件 | `[源文件]业务对象` | `[源文件]交易信息` |
| 贴源表 | `[贴源]业务对象` | `[贴源]交易信息` |
| 报文结构 | `[报文]业务对象` | `[报文]组织机构基本情况表` |
| 报表结构 | `[报表]业务对象` | `[报表]外债签约信息` |

监管报文表英文名必须优先使用发文中的接口文件类型名。命名规则通常为应用类型代码加接口文件类型代码，例如 `FALEJ` 对应 `FAL + EJ`，即 `E03-3表：外资承运人国际运输服务统计表（仅国际运输调查主体填写）`。不要使用 `SAFE_MSG_E03_3`、`E03_3` 或物理落地表名替代正式报文英文名。

## 4. 字段元模板

```markdown
## 字段元：表英文名

| 序号 | 英文字段名 | 中文字段名 | 类型 | 长度 | 格式 | 是否必填 | 是否主键 | 字段说明 | 码值说明 | 证据来源 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | REC.CUSTCODE | 主体标识码 | string | 18 | 字符型，18 | 是 | 否 | 发文中的字段口径、校验要求 | 可空或码值集合名 | 发文第x章/SQL/代码 | 可空 |
```

### 字段元填写规则

| 属性 | 规则 |
| --- | --- |
| 序号 | 字段展示顺序；源文件按文件字段顺序，数据库按物理列序，XML 按发文或 XML 节点顺序 |
| 英文字段名 | 必须是原始字段名；XML 报文使用完整路径，例如 `REC.CUSTOMS.CUSTOM.CUSTOMN` |
| 中文字段名 | 必须来自发文、数据库注释、字段说明或业务确认；无证据时留空或写待确认 |
| 类型 | 使用标准类型：`string`、`decimal`、`int`、`bigint`、`date`、`datetime`、`timestamp`、`boolean`、`xml_node`、`待确认` |
| 长度 | 只写长度或精度，例如 `18`、`22,2` |
| 格式 | 写监管原始格式、日期格式、定长/最长位数等，例如 `字符型，18`、`YYYYMMDD` |
| 是否必填 | `是`、`否`、`条件必填`、`待确认` |
| 是否主键 | `是`、`否`、`待确认` |
| 字段说明 | 写业务含义、填报要求、校验规则、口径说明 |
| 码值说明 | 推荐写码值集合名；大量码值应单独整理为码值元 |
| 证据来源 | 必须能定位到原始依据 |

禁止写法：

| 问题 | 禁止示例 | 正确处理 |
| --- | --- | --- |
| 中文名复制英文 | `customer_id` | 无证据时留空或写待确认 |
| 类型混入长度 | `varchar(32)` | 类型写 `string`，长度写 `32`，格式可写 `varchar(32)` |
| 格式混入类型 | `字符型，18` | 类型写 `string`，长度写 `18`，格式写 `字符型，18` |
| Mapping 写进字段说明 | `取 CIF2.TXT.customer_id` | 写入 Mapping 模板或字段关联，不写进字段说明 |
| 推测 XML 节点 | 用中文名反推英文节点 | 没有节点证据时不建字段元 |

## 5. 源文件字段补充模板

源文件表元和字段元需要额外说明文件解析规则。

```markdown
## 源文件字段：文件名

| 序号 | 文件字段名 | 中文字段名 | 类型 | 长度 | 解析方式 | 分隔符/定长规则 | 对应贴源表 | 对应贴源字段 | 证据来源 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | customer_id | 客户号 | string | 待确认 | 分隔符 | \| | CifTab | customerId | Java代码/文件样本 | 文件入库承接关系，不是源文件自身 Mapping |
```

填写规则：

1. `序号` 必须来自文件规范、文件样本或 ETL 代码。
2. `对应贴源表/字段` 只表示入库承接关系。
3. 不得把 `源文件 -> 贴源表` 写成源文件自己的 Mapping 来源逻辑。
4. 源文件如何生成没有证据时，源文件 Mapping 保持为空。

## 6. 监管 XML 报文补充模板

```markdown
## XML 报文：报文英文名

| 属性 | 填写内容 |
| --- | --- |
| 所属库 | SAFE_MESSAGE |
| 英文名 | 例如：FALZA |
| 中文名 | 例如：[报文]Z01表：单位基本情况信息 |
| 数据层级 | 报文层 |
| 载体类型 | XML报文 |
| 表口径 | 该报文承载的监管接口业务对象 |
| 证据来源 | 发文、XSD、XML 示例、接口规范 |
| 备注 | 可空 |

| 序号 | XML路径 | 中文名 | 类型 | 长度 | 格式 | 是否必填 | 节点类型 | 字段说明 | 证据来源 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | REC | XML容器节点 | xml_node |  |  | 是 | 容器节点 | XML 容器节点 | 发文第x章 |  |
| 2 | REC.ACTIONTYPE | 操作类型 | string | 1 | 字符型，1 | 是 | 叶子节点 | A 新增、C 修改、D 删除 | 发文第x章 |  |
```

填写规则：

1. XML 报文表英文名使用发文接口文件类型名，例如 `FALEJ`、`EXDAN`、`BOPA`。
2. XML 字段英文名使用完整 XML 路径。
3. 容器节点可以作为字段元，类型写 `xml_node`。
4. 叶子节点按监管数据字典维护中文名、类型、长度、格式、校验说明。
5. 只有业务描述或“见某系统”，没有节点名或字段名时，不生成正式字段元。
6. XML 结构不是 Mapping；报文节点数据来源需要 SQL、存储过程、组装代码或 Mapping 文档证据。

## 7. Mapping 模板

只有确实知道“数据怎么来的”时才填写 Mapping。

```markdown
## Mapping：目标表英文名

### 场景：场景名称

| 目标字段 | 目标中文名 | 涉及字段 | 处理逻辑 | SQL转换 | 证据来源 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| customer_id | 客户号 | CIF2.TXT.customer_id | 直取 | customer_id | Java代码/SQL/Mapping文档 | 可空 |
```

### Mapping 填写规则

| 属性 | 规则 |
| --- | --- |
| 目标字段 | 目标表中的真实字段英文名 |
| 目标中文名 | 目标字段已核验中文名 |
| 涉及字段 | 必须是真实字段元路径，例如 `CIF2.TXT.customer_id` |
| 处理逻辑 | 直取、常量、条件判断、聚合、码值转换、拼接、截取、日期转换等 |
| SQL转换 | 可执行或可翻译为 SQL 的表达式；无法转换时写 `无法转换` 并说明原因 |
| 证据来源 | SQL、存储过程、代码、Mapping 文档、业务确认 |

禁止写法：

1. 不要把展示名、中文名、驼峰推测名写入 `涉及字段`。
2. 不要把源文件入库承接关系当成源文件自己的 Mapping。
3. 不要在没有来源证据时填写 `直取`。
4. 不要用一段长备注替代结构化 Mapping。

## 8. 码值元模板

```markdown
## 码值元：码值集合名

| 值 | 说明 | 备注 | 排序 |
| --- | --- | --- | --- |
| A | 新增 | 可空 | 1 |
| C | 修改 | 可空 | 2 |
| D | 删除 | 可空 | 3 |
```

填写规则：

1. 一行一个码值。
2. `值` 必须是真实入库或报送值。
3. `说明` 写业务含义。
4. `备注` 只写特殊条件、历史说明或适用范围。
5. 字段元中只绑定码值集合，不长期堆大段码值文本。

## 9. 待确认项模板

```markdown
## 待确认项

| 对象类型 | 对象名 | 属性 | 问题 | 需要补充的证据 |
| --- | --- | --- | --- | --- |
| 字段元 | CIF2.TXT.customer_id | 中文字段名 | 当前只有英文名，无中文名证据 | 文件规范、业务确认或数据库注释 |
```

对象类型可选：

```text
库元
表元
字段元
码值元
场景元
Mapping规则元
涉及字段元
动作元
```
